# Java fast path (2026-11-20)

`FastJava` runs a method without Kahlua's `pcall` when the function Lua resolved is still the exposer's own `LuaJavaInvoker` for a single, non-overloaded instance method. Lookups still go through `tableget`, so Lua patches to Java methods win. Arguments and results use PZ's `KahluaConverterManager`, and exceptions are raised through `pcall` the way `LuaJavaInvoker` raises them. Overloaded methods (`MultiLuaJavaInvoker`), varargs and static methods, and any argument Kahlua wouldn't convert all take `pcall`. About 94% of exposed instance methods aren't overloaded (by name per class in Wrench.Game.Java's generated wrappers; inherited overloads aren't counted, so this is an upper bound).

Checked against `pcall` on the real Kahlua: `getR`, `getRedByte`, `size`, `isEmpty`, `contains` and `get(1.7)` (truncated to 1, as Kahlua does) match. Wrong argument types or counts fall back and get Kahlua's own errors, and a Lua-patched `getR` isn't fast-pathed. Without the game, an exception thrown by the method can't be compared, because `pcall`'s own stack-trace printing needs `UIManager`.

Same machine as `2026-11-20.md`. `color.Darker` is overloaded, so it still takes `pcall`.
